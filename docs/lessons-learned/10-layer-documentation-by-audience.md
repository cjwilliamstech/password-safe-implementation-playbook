# Lesson: Layer Documentation by Audience

A confidential technical/security framework doc (for internal security review), a
plain-language guide (for non-technical stakeholders and application teams), and a
narrow technical reference (e.g. a firewall-rules-only doc for the network team) each
get read by different people who need different levels of detail.

**Takeaway:** one document trying to serve all three audiences serves none of them
well — write separate, purpose-built documents rather than one document with
everything in it.
